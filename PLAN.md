# Plan: getenv, mktemp_dir, path_lookup and fs_read_status builtins (#1404, part of #1398)

## Goal
Add four builtins to BOTH compilers so the native verifier can locate the solver and make its temp dir without `sh -c`, and let callers tell an empty file from a failed read. Closes #1404 acceptance criteria; migrating `compiler/verifier.vow` off `sh -c` is a follow-up (out of scope).

## Assumptions
(decided without an operator; override in review)
- **fs_read error reporting = side-channel status, not a signature change.** `fs_read(path) -> String` keeps its type (≈15 callers in `compiler/*.vow`, tests, examples); a new `fs_read_status() -> i64 [read]` reports the outcome of the calling thread's most recent `fs_read`. Mirrors the existing `process_get_stdout` / `fs_status(handle)` "read it immediately after" pattern and needs no Option<String>/Result builtin ABI (no builtin returns one today). Status codes: `0` ok (including empty file), `1` not found, `2` permission denied, `3` other I/O error (incl. directory, read error), `4` invalid path (null/non-UTF-8). `-1` = no `fs_read` yet on this thread. Thread-local (parallel codegen/verify threads must not race). Rejected alternatives: changing `fs_read` to return `Option<String>`/Result (breaks every caller, new ABI, dual-compiler churn); `fs_read` returning a sentinel (no sentinel is distinguishable from file content).
- **getenv**: `getenv(name: String) -> String [read]`; returns `""` when unset, empty, non-UTF-8 name/value, or name is empty/contains `=` or NUL. Unset vs empty deliberately not distinguished (all intended callers treat both as "not configured"); no `env_is_set` added (surface minimal per language principles; follow-up if needed).
- **mktemp**: only the directory form the verifier uses today (`mktemp -d "${TMPDIR:-/tmp}/vow-verify.XXXXXXXXXX"`, `compiler/verifier.vow:422`): `mktemp_dir(prefix: String) -> String [io]` creates `<$TMPDIR or /tmp>/<prefix>.XXXXXXXXXX` via libc `mkdtemp` (atomic, mode 0700), returns its absolute path, or `""` on failure or if `prefix` is empty/contains `/` or NUL. Caller removes it with `fs_remove_dir`. File form (`mktemp_file`) is a follow-up.
- **executable lookup**: `path_lookup(name: String) -> String [read]` ≈ `command -v` minus shell builtins/aliases: if `name` contains `/` test it directly, else search `$PATH` entries in order (empty entry = `.`), returning the first regular file with any exec bit (`access(X_OK)`); `""` if none / empty name.
- Effects: `getenv`/`path_lookup`/`fs_read_status` `[read]`, `mktemp_dir` `[io]` (consistent with `fs_mkdir` `[io]`, `args` `[read]`).
- Checked ADR-2026-10-08-1421, epic #1398 (D12/G13) and sibling issues: they only say these builtins land in both compilers; no names or `fs_read` error shape are pinned, so the design here stands.
- Verifier model: all four are unmodeled externs → callers are Skipped fail-closed (same as `hash_str`). No C-emitter change; catalogue `verifier_model` left unset like `hash_str`.

### 2. Runtime implementation details (`vow-runtime/src/lib.rs`)
- Helper `vow_str_arg(ptr) -> Option<&str>` style: `sanitize_on_read`, null → `None`, UTF-8 check (reuse the pattern in `fs_read_bytes`/`__vow_fs_open`).
- `getenv`: `std::env::var_os` → UTF-8 → bytes; reject empty/`=`/NUL names.
- `path_lookup`: split `PATH` via `std::env::split_paths`; check `metadata().is_file()` && `libc::access(X_OK)==0`.
- `mktemp_dir`: build C template, `libc::mkdtemp`, return path; retry-free (mkdtemp already loops internally).
- `fs_read_status`: `thread_local! { static LAST_FS_READ_STATUS: Cell<i64> }` initial `-1`; `fs_read_bytes` returns `Result<Vec<u8>, i64>` (map `io::ErrorKind::NotFound→1`, `PermissionDenied→2`, else `3`; null/non-UTF-8 path→4) and records status before the arena lock is taken. `__vow_fs_read` and `_in_arena` both record. Note `fs_read_bytes` is documented "takes no arena lock" — keep that.
- Testability: implement pure inner helpers taking explicit inputs (`path_lookup_in(path_var: &str, name: &str)`, `mktemp_dir_in(base: &Path, prefix: &str)`, `fs_read_outcome(path)`); extern wrappers only read the environment (`PATH`, `TMPDIR`). Unit tests call the helpers directly and never `set_var`.
- `TMPDIR` edge cases: empty `TMPDIR` is treated as unset (→ `/tmp`); strip trailing `/`s from `TMPDIR` before appending `/<prefix>.XXXXXXXXXX`.
- Free any C allocations (CString) on all paths; no leaks (production-quality rule).

## Risks
- **Binary fixed point**: generated blocks must be produced by the script, not hand-edited; `ir.vow` `fresh_arena_base_extern` is a byte-indexed decision tree keyed on symbol length — regenerate, don't patch. Order of operations.json entries affects output; append at the end.
- **Missing `_in_arena` variant** for a heap_fresh symbol → link failure in region-routed code; every String-returning builtin needs both symbols (bench/memory `alloc_loop_fresh_builtins` and `fresh_builtins_region_routing` tests exercise this).
- **Thread-local status**: if Vow codegen runs `fs_read` on one thread and `fs_read_status` on another (parallel runner), status is wrong; document "same thread, immediately after". Verify the compiler's own parallelism uses processes (it does for verify) before any verifier code relies on it.
- **Clippy `-D warnings` incl. tests**; `unsafe` blocks around libc; env mutation is kept out of tests via the pure-helper split.
- **Seed**: `scripts/seed.toml` does not exist yet (checked), so no pinned-seed type-check skew for new `tests/run` fixtures; once a seed lands, fixtures using these builtins need the seed bumped or `--no-verify`.
- **Untouched invariants**: no grammar/IR/opcode change, so `parse → print → parse` idempotency, BTreeMap/HashMap determinism and the clif-shim stack-slot layout are unaffected; only generated symbol tables change.
- **Codecov patch gate (95%)**: runtime branches (each error code, PATH ordering, mkdtemp failure) need Rust unit tests because the `.vow` corpus runs an uninstrumented binary.
- **Sandbox**: e2e run tests may SKIP/FAIL without linked runtime (known); verify against clean main before blaming change. `mktemp_dir` test depends on writable `$TMPDIR`.
- **Help/skill staleness**: grammar.md edits must be followed by `generate_help.py`, else `check_help_coverage.py` fails in `full_test.sh`.
- **Dual compilers**: every registration lands in both `vow-types/src/env.rs` and `compiler/env.vow` in the same PR; the verifier-only exception does not apply (these are runtime builtins).
