# Plan: self-hosted `--replay-cex` for files that define `main` (#1550)

## Goal
Make `vowc verify --replay-cex` replay counterexamples when the entry file already defines `main`, so
the self-hosted compiler agrees with the Rust one (`generate_replay_harness`, `vow/src/replay.rs:311`)
and the P5 "every counterexample replays" oracle (epic #1398) is no longer vacuous for programs with
`main`. Remove the "defines main" limitation from `docs/spec/cli.md`.

## Decision (records the issue's acceptance item 1)
- **Option 2, rename**: the self-hosted compiler rewrites the entry file's top-level `fn main` to
  `fn __replay_orig_main` using the AST fn span **start**, then appends the synthesized `fn main`.
  Not option 1 (strip by span) because the self-hosted parser clamps every packed span length to
  65535 bytes (`span_pack_to_here`, `compiler/parser.vow:129`; `span_pack` requires `len < 65536`),
  so a `main` longer than 64 KiB would be truncated and corrupt the harness. The start offset is
  exact (`start * 65536 + len`, unbounded start). Rename needs only the start.
- Not option 3 (IR-level entry): larger, changes codegen/verify surface, keeps the temp-file rule.
  Not option 4 (env entry override): needs a language/runtime decision and violates the
  new-surface criteria in CLAUDE.md. Both stay open as future work, not needed here.
- **Dual-compiler stance**: the Rust compiler already replays files with `main` (removal by span;
  u32 span lengths so no clamp). Behavior is therefore already the target; this change is
  self-hosted-only code, *plus* shared fixtures + a cross-compiler gate that pin both. No
  behaviour-visible Rust change is planned. Rust removal and self-hosted rename are
  outcome-equivalent because the original `main` never runs in a harness.
- **Scalar/Vec/String gaps**: out of scope (separate fixes, different code: reconstruction, not
  entry splicing). Recorded as follow-ups below.

## Assumptions
- A `main` defined in a `use`d dependency file is not the entry file's `main`; the harness is built
  from the entry file text only, so only items with `item_files[i] == path` count (best guess).
- Rename (not removal) is safe: the original `main` already compiled in the user's build, vow ids are
  per-function-local, and the harness builds with `--no-verify --mode debug`.
- The synthesized name `__replay_orig_main` colliding with a user fn is treated as a compile failure
  -> existing `replay: harness did not compile` skip.

## Steps (TDD slices, ordered)

### 1. RED: fixture + gate, no production change
- Add `tests/verify-fail/replay_confirm_with_main.vow` modelled on `replay_confirm_scalar.vow`
  (`pinned(x)` with `requires: x == 3`, `ensures: result == 0`, `// TEST: replay confirmed`) plus
  `fn main() -> i32 [io] { print_i64(0); 0 }` (main does not call `pinned`, so no extra CEs).
- In `scripts/full_test.sh` Section 4c add, next to the `counterexample-violation` block, a
  `// TEST: replay <status>` check: run `$RUST verify --replay-cex --no-cache` and
  `run_self verify --replay-cex --no-cache`, require every counterexample's `replay` equal to the
  directive on both sides (same python snippet style; fail names `${name}/verify-fail-replay`). Compare the `replay` *status*
  only, not `replay_reason`: reasons differ between compilers by design ("did not compile (msg)" vs
  "did not compile", diverge texts), so do not route this through `compare_full_json`.
  Today's `replay_*` fixtures already carry the directive but only Rust is checked
  (`verify_eval.py`), so this closes the claimed-but-absent cross-compiler agreement.
- Run the new fixture with the self-hosted binary: expect `skipped` (red) and Rust `confirmed`.

### 2. GREEN: locate main by AST, not text
- New `compiler/replay_main.vow` (`module ReplayMain`, `use ast`, `use diag`):
  - `fn replay_entry_main_start(m: Module, item_files: Vec<String>, path: String) -> i64`:
    iterate `m.items`; for `item_kind == ITEM_FN()` and `item_files[i] == path`, compare
    `arena_str(a, fn_name_sid(a, id)) == "main"`; return `span_unpack_start(fn_span(a, id))` or `-1`.
    Skip `is_declaration` fns (extern-style decls have no body to rename; none are named `main`).
  - `fn replay_rename_main(src: String, start: i64) -> String`: validate `src[start..start+2] == "fn"`,
    skip ASCII whitespace, require the next 4 bytes `main` followed by a non-identifier byte
    (`is_ident_cont` in lexer.vow:38); return `src[..name_start] + "__replay_orig_main" + src[name_end..]`,
    or `""` when validation fails (caller skips with a reason). Byte-based (`byte_at`/`substring`),
    no `contains`.
- `compiler/main.vow`: thread `main_start: i64` through `verify_finish` (called from `run_verify`
  and `run_verify_native`, both already hold `fr: LoweredFrontend`) and `run_build_cmd`
  (line ~2252), then `replay_all` -> `replay_one_ce`. Compute once per run with
  `replay_entry_main_start(fr.merged, fr.item_files, path)` only when `--replay-cex` is set.
- In `replay_one_ce` delete the `src.contains("fn main(")` skip (824-826); when `main_start >= 0`
  build `harness = replay_rename_main(src, main_start)` (empty -> `replay_skip("replay: could not
  locate the entry file's main")`), else `harness = src`. Everything after (synthesized `fn main`,
  temp tag, compile, run, classification) is unchanged. Keep the `ce.function == "main"` skip.
- Register `replay_main` in `scripts/concat_vow.sh` FILES before `main` and `use replay_main` in
  `compiler/main.vow`.
- Update the header comment (main.vow:664-667) to drop "an entry file that already defines main".
- Slice 1's fixture goes green; re-run the existing `replay_*` fixtures (unchanged outcomes).

Design note: keep the module's public surface to one deep entry point
`replay_harness_base(m, item_files, path, src) -> String` (returns the source with the entry `main`
renamed, `src` unchanged when it has none, or `""` when the offset cannot be validated); the
locate/rename pieces stay private helpers. Callers compute nothing else, so `main_start` need not be
threaded as a bare i64: pass `fr.merged`/`fr.item_files` (or the base `src`) instead if that is
simpler. Tests below drive the entry point.

### 3. Unit tests for the helpers (`compiler/tests/test_replay_main.vow` [new])
Run with `build/vowc test compiler/tests/test_replay_main.vow`. Parse sources via
`frontend_parse_source_into` as `compiler/tests/test_checker_shift_count.vow` does. Cases:
- main found -> start equals offset of `fn`; absent -> `-1`.
- `fn main(` inside a string literal and a `//` comment, no real main -> `-1`
  (regression of the old text search).
- item from another file (`item_files` entry != path) named `main` -> ignored.
- `fn  main ()` spacing, `pub`-like prefix preserved, rename keeps bytes before/after exact.
- stale/wrong offset (not at `fn`, or name not `main`, or `mainly`) -> `""`.
- >64 KiB `main` body: start still exact, rename leaves the tail intact (guards the clamp).

### Known divergence (not fixed here; file a follow-up issue)
Rust's `bundle.module()` is the merged module (`vow/src/frontend.rs:46`, with a parallel
`item_files()`), and `generate_replay_harness` strips the *first* `main` in it, which could be a
`use`d dependency's span applied to entry-file text. The self-hosted path filters by `item_files`
and, when only a dependency defines `main`, appends a second `main` -> compile failure -> an honest
`skipped`. Fixing Rust means threading `item_files` into `replay_one` plus a Rust test; kept out of
this PR to stay surgical (codecov-patch, clippy, scope). File a follow-up and link it from the ADR.

## Verification surface
- No contracts, C emitter, or IR changes -> no new ESBMC obligations and C parity unaffected.
- New helpers are pure and total; give them tight contracts only where they express real domain
  facts (`start >= 0` for `replay_rename_main`); do not bound lengths for the verifier. Mark any
  helper ESBMC cannot prove (string scanning loops) unverifiable rather than distorting contracts.
- `compiler/` is verified at bootstrap, so a new module must verify or be marked appropriately.

## Risks
- **Fixed point / codegen ordering**: new module in `concat_vow.sh` changes the concatenated build;
  verify with the bootstrap triple (stage1==stage2 hashes). No `HashMap` use (use Vec scans).
- **Span clamp (65535)**: mitigated by using only the start offset; validated by the >64 KiB unit test.
- **Offsets are bytes of the entry file as lexed**: CRLF/BOM would shift nothing (lexer offsets are
  byte offsets), but `replay_rename_main` validates `fn`+`main` at the offset and skips otherwise,
  so a stale offset can never corrupt the harness silently.
- **Dependency modules**: `merged.items` contains dep items; filter by `item_files` (see Assumptions
  and Known divergence).
- **Renamed main stays in the program**: it is compiled but never called by the harness. A user fn
  that itself calls `main()` now resolves to the *synthesized* `main` (rare): it type-checks or fails
  on signature, unlike Rust's removal, where the name is simply gone. Either way the outcome is a
  compile-failure skip or an equally valid replay; no corruption.
- **THREE_CLAIMS flips from skipped to a real verdict**: pin the real value; a `diverged`/`aborted`
  there would be a genuine native-model finding and must be reported, not hidden.
- **Harness temp files** are written next to the fixture (`__vow_replay_<fn>_<vow_id>`); Slice-1
  gate runs fixtures sequentially, preserving the no-overwrite rule.
- **Prompt/skill drift**: `scripts/check_help_coverage.py` fails if cli.md edit is not regenerated.
- **Codecov patch 95%**: `.vow` corpus runs uninstrumented; any Rust edit (Step 7) needs its own
  Rust unit test.
- **Commit hygiene**: lower-case conventional subjects, e.g.
  `feat(verify): replay counterexamples for files that define main`; squash-merge title <= 92 chars.

## Out of scope / follow-ups
- Replaying `Vec` params in the self-hosted compiler (Rust already does; reconstruction code).
- `String`, maps, structs, enums, references in either compiler.
- IR-level replay entry (option 3) and runtime entry override (option 4).
- Removing the temp-file/no-overwrite rule; changing the harness tag scheme.
- Making Rust rename instead of remove (equivalent outcome; no churn).
- Mutation sweeps, parity.py comparator changes beyond the Section 4c gate.
- The Rust multi-module `main` selection fix (follow-up issue, see Known divergence).
