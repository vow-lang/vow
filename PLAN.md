# Plan: round-trip proptest covers Cast + nested unary; fix `-!x` printer bug (#628)

## Goal
Make the `vow-syntax` print→parse proptest exercise `Cast` and arbitrarily nested unary/binary operands so printer
parenthesization bugs fail CI, and fix the printer bug this surfaces (`Neg(Not x)` prints `-!x`, lexed as `MinusChecked`).

## Assumptions (best guess; no operator available)
- Issue text is partly stale. Verified against `main` (e6aa9bbb):
  - `Question` is already generated (`vow-syntax/tests/proptest_arb.rs:107,214`) and `print_parse_roundtrip` already asserts
    span-stripped AST equality (`proptest_roundtrip.rs:352-360`). No work needed for either.
  - `Borrow` no longer exists: `ExprKind` has no Borrow variant and the parser rejects `&expr` (`parser/expr.rs:268`, #1488). Out of scope.
  - Remaining real gaps: no `Cast` generation; `arb_unop_expr` takes only leaf operands (`proptest_arb.rs:175-189`);
    `expr_in_fn_roundtrip` (`proptest_roundtrip.rs:436-475`) asserts only idempotence, not AST equality.
- Known live bug (from reading `printer.rs:566-576` and `lexer.rs:89-93`): `UnaryOp{Neg, UnaryOp{Not, x}}` prints `-!x`, which the lexer
  turns into `MinusChecked` -> parse error. `contract_text.vow:243-258` has the identical logic, so the same bug exists in the
  self-hosted compiler (dual-compiler rule applies). `!!x`, `--x`, `!-x` lex fine (`!` only pairs with `=`; `-` only with `!`/`>`).
- Reviewed and expected-correct (the new tests must confirm, not assume): unary binds looser than postfix
  (`-a as u64` = `Neg(Cast a)`, `-a?` = `Neg(Question a)`; `parser/expr.rs:95-125,245-262`), so `Neg(Cast)` needs no parens;
  `Cast(Unary)`, `Question(Unary)`, `Question(Binary)` get parens already (`printer.rs:517-531,689-701`).
  If the widened generator finds more failures, fix each with the smallest printer change in both compilers, one commit per bug.
- Cast targets in the generator are limited to scalar names (`is_scalar_type_name`, `parser/expr.rs:10`): `parse_cast_target`
  treats other names as generic-capable types, and `arb_type_name` includes `str`/`bool`, which may not be scalar. Do not weaken the printer to cover that.

## Steps (TDD slices; each its own commit, Conventional Commits, lower-case subject)

### 1. Red: nested-unary generator exposes `-!x`
- `proptest_arb.rs`: change `arb_unop_expr(depth)` to take `arb_expr_inner(depth)` as the operand (drop the "leaf only" comment and the `_depth` underscore).
  Keep `arb_expr_or_if` using it. Operands that are `if`/block-like are not generated by `arb_expr_inner`, so no new `if x {} + y` hazard.
- Run `cargo test -p vow-syntax --test proptest_roundtrip` -> expect `print_parse_roundtrip`/`expr_in_fn_roundtrip` to fail on `-!x` (parse error).
  Commit the generator change together with the fix in step 2 if the red commit would break CI; otherwise commit red as `test(syntax): ...` only when the branch is not pushed in between.

### 2. Green: fix `-!x` in both compilers
- `printer.rs` UnaryOp arm: parenthesize the operand when it is `BinaryOp` (existing) OR when `op == Neg` and the operand prints starting with `!`
  (operand is `UnaryOp{Not,..}`; also covers any operand whose printed form begins with `!`). Simplest correct rule: `Neg` over `UnaryOp{Not}` -> `-(!x)`.
  Do not parenthesize `!!x`/`--x`/`!-x` (they round-trip; avoids churn in canonical form).
- `compiler/contract_text.vow` EXPR_UNOP arm: same rule (check `expr_tag(operand)==EXPR_UNOP() && expr_a(operand)==UNOP_NOT()` when `op != UNOP_NOT()`), using `parenthesize_text`.
- Unit tests in `printer.rs` tests module: `-(!a)`, plus no-paren pins for `!!a`, `--a`, `!-a`, `-a as u64`.
- Parity: add rows to `contract_text_postfix.vow` (`requires: -(!b) == 1` style; use types that typecheck as the file's existing rows do),
  matching `.expected` line(s), and the same row to `contract_text_postfix_canonical.vow`. Verify with `build/vowc contracts` and `target/release/vow contracts` on the fixture,
  and `cargo test -p vow-ir --test contract_text_forms`.

### 3. Red/green: generate Cast
- `proptest_arb.rs`: add `arb_cast_expr(depth)` = `(arb_expr_inner(depth), arb_scalar_type_name())` -> `ExprKind::Cast{expr, target_ty: Type::Named{..}}`;
  `arb_scalar_type_name` = the integer/float subset of `arb_type_name` (i8..i128, u8..u128, f32, f64) -- confirm against `is_scalar_type_name` (`parser/expr.rs:10-25`).
  Add `1 => arb_cast_expr(depth - 1)` to `arb_expr_inner` and `arb_expr_or_if`.
- Expect pass (printer already parenthesizes non-atomic cast operands and `parse_cast_target` handles `<`/`<<`). Any failure -> fix printer + `contract_text.vow` and add parity rows per step 2's pattern.
