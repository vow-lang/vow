# Plan: self-hosted lexer reports unterminated strings, unterminated escapes and unknown characters (#642)

## Goal
Give the self-hosted lexer a diagnostic channel (the shared `DiagCtx`) and emit
errors for the three inputs it currently swallows, byte-for-byte matching the Rust lexer's
message/span/count. Lexical-error behaviour of the Rust lexer is the reference; only one
Rust-side change (error code, see Assumptions) is proposed.

## Assumptions
- Diagnostic channel = `DiagCtx` + file path, new `lex_into(src, dctx, file)`; existing
  `lex(src)` stays as a thin wrapper over it with a throwaway `diag_ctx_new()` so the ~10 test
  callers (`compiler/tests/test_checker_*.vow`, `test_lower_*.vow`) and `decl_text.vow:262` are
  untouched (best guess; mirrors how `parse_module` wraps `parse_module_into`, parser.vow:114-118).
  `decl_entry_module_name` (decl_text.vow:261) runs only after `frontend_prepare_path` already
  reported errors (decl_main.vow:43-48), so the discarded diagnostics there are safe.
- Stop at the first lexical error, like Rust (`tokenize()` returns `Err` at first failure and
  `parse_module` returns an empty `<error>` module with exactly 1 diagnostic, vow-syntax/src/parser/mod.rs:706-724):
  emit one diagnostic, discard tokens so far, return `[EOF]` only. `parse_module_into` over `[EOF]`
  must yield an empty module with zero extra errors, so `error-count` is 1 in both compilers.
  Verified by reading: `frontend_prepare_path_traced` skips `check_module` when `diag_ctx_has_errors(dctx)` (frontend.vow ~line 303),
  so an empty root or dependency module cannot cascade into checker errors; implementer still confirms empirically, incl. a
  lex error inside a `use`d module (add a `tests/multi/`-style case if cheap). Fallback if the parser itself adds a diagnostic on
  `[EOF]`: return the tokens lexed so far plus EOF.
- Error code: Rust emits `InvalidCharacter` for *unterminated string/escape* (lexer.rs:398-400, 420-422)
  although spec `docs/spec/errors.md:9-20` documents `UnterminatedString`, the self-hosted
  `EC_UNTERMINATED_STRING` (diag.vow:11) and Rust `ErrorCode::UnterminatedString` (vow-diag/src/lib.rs:40) exist
  and are unused by any lexer. Decision: switch BOTH compilers to `UnterminatedString` for those two
  cases (spec is authoritative per CLAUDE.md), as its own slice/commit so it can be dropped. Unknown
  character stays `InvalidCharacter`. (If a reviewer prefers zero Rust behaviour change, skip slice 1
  and use `EC_INVALID_CHARACTER()` for all three; nothing else in the plan changes.)
- Out-of-range int/float literals keep their existing in-band `tok_invalid_int`/`tok_invalid_float`
  mechanism (parser.vow:1016-1023); not unified here.
- Invalid UTF-8 inside string literals (Rust lexer.rs:408-412) is unreachable: self-hosted sources
  are read as raw bytes; not addressed.

## Reference behaviour to match (Rust)
- Unterminated string (EOF before closing `"`, including `"abc\"`): message `unterminated string literal`,
  span `(start_of_open_quote, eof - start)`.
- Trailing backslash as last byte: message `unterminated string escape`, span `(start, eof - start)`
  (the backslash is included). NB: today the self-hosted `92 && pos+1 < src_len` guard pushes the lone `\`
  as a normal byte; the new code must detect `\` at `pos+1 == src_len` explicitly.
- Unknown byte `b`: message `unexpected character '<c>'` where `<c>` is `b as char`; span `(start, 1)`.
  For `b < 128` that is the byte; for `b >= 128` Rust prints the Latin-1 codepoint, i.e. UTF-8
  `[0xC0 | b>>6, 0x80 | b&0x3F]` — reproduce this so messages are byte-identical.
- Valid-token set is unchanged; comments (`//`) and whitespace unaffected.

## Steps (TDD slices, one commit each)

### 1. Rust: unterminated string/escape use `UnterminatedString`  (separable)
- Red: `vow-syntax/src/lexer.rs` tests — change `lex_unterminated_string_escape_is_error` (line 570) to expect
  `ErrorCode::UnterminatedString`; extend `lex_unterminated_string_is_error` (579) to assert code+message
  `unterminated string literal` and span `(0, 13)`; add `lex_unexpected_character_reports_span_and_message`
  (`"@"` → `InvalidCharacter`, `unexpected character '@'`, span `(0,1)`).
- Green: lexer.rs:398-400, 420-422 → `ErrorCode::UnterminatedString`.
- Run `cargo test -p vow-syntax`; grep `tests/` for fixtures asserting `InvalidCharacter` on unterminated strings (none found: only `tests/error/f64_literal_overflow.vow`).

### 2. Self-hosted: `lex_into` skeleton + unterminated string  (red→green)
- Red: [new] `compiler/tests/test_lexer_diagnostics.vow`: `lex_into("\"abc", dctx, "f.vow")` →
  `dctx.error_count == 1`, diag code `EC_UNTERMINATED_STRING()`, message `unterminated string literal`,
  `span_start == 0`, `span_len == 4`, tokens == `[EOF]`. Also: valid string `"abc"` → 0 errors, 2 tokens (guards no regression);
  `"abc\"` (escaped quote then EOF) → unterminated.
- Green (`compiler/lexer.vow`): rename body of `lex` to `lex_into(src, dctx, file)`; add `lex(src) -> Vec<Token>` wrapper
  (`lex_into(src, diag_ctx_new(), String::from(""))`). Add a small helper
  `lex_fail(dctx, file, code, msg, start, len) -> Vec<Token>` (builds via `diag_error` + `diag_ctx_emit`, returns
  `[EOF at pos]`) so each error site is a one-line `return`. Replace lines 351-353 (`if pos < src_len { pos = pos + 1; }`)
  with: if `pos >= src_len` → `return lex_fail(... EC_UNTERMINATED_STRING() ...)`, else consume the closing quote.
- Reuses: `diag_error` (diag.vow:106), `diag_ctx_emit` (diag.vow:261), `make_token` (token.vow), `empty_str` (lexer.vow:196).

### 3. Self-hosted: unterminated escape
- Red: test `"abc\` → code `EC_UNTERMINATED_STRING()`, message `unterminated string escape`, span `(0, 5)`.
- Green: in the string loop, on `byte_at(pos) == 92`: if `pos + 1 >= src_len` → `lex_fail(... "unterminated string escape", start, src_len - start)`;
  else existing escape table. Keep the unknown-escape fallthrough (`\q` → `\`,`q`) unchanged (matches Rust 433-436).

### 4. Self-hosted: unknown character
- Red: tests `@` → `EC_INVALID_CHARACTER()`, message `unexpected character '@'`, span `(0,1)`; `a $ b` → span start 2; a
  non-ASCII byte (e.g. src with byte 0xC3 outside string/comment) → message equals Rust's two-byte encoding of U+00C3;
  non-ASCII inside a string and inside a `//` comment → 0 errors.
- Green: final `else` (lexer.vow:545) → build message (`unexpected character '` + char + `'`) via `String::from` / `push_byte`
  (helper `unexpected_char_msg(b)` next to `unrepresentable_suffix_msg`, lexer.vow:204) and `return lex_fail(...)`.

## Verification surface (ESBMC / C model)
- No `vow` blocks added or changed; `lex`/`lex_into` have none today (only `span_len` has contracts, unchanged). No ESBMC property
  needed, no change to `c_emitter.{rs,vow}`, so no C-parity risk. If the implementer is tempted to add a contract on `lex_fail`,
  don't (true contract is trivial; bounds would be verifier artifacts).
- `tests/run/` / `examples/`: no growth needed; `tests/error/` fixtures above are the surface.

## Risks
- **Hidden stray characters in existing corpus**: the self-hosted lexer used to skip unknown bytes, so a `tests/run/`, `tests/verify*/`
  or `compiler/` file that only self-hosted accepted would now fail. Mitigation: bootstrap (compiler sources) + `full_test.sh`; Rust
  already rejects them so any such file is already a divergence to fix, not weaken.
- **Binary fixed point**: lexer change alters stage1 codegen but is deterministic (no `HashMap`); verify stage1==stage2 via bootstrap.
  New helper must not rely on iteration order.
- **Cascade parity**: if `[EOF]`-only token list produces any parser diagnostic, `error-count` ≠ Rust's 1 (see Assumptions fallback).
- **Parity of non-ASCII message**: only matters for exotic input; covered by the unit test in slice 4.
- **`diag_ctx_emit` source registration**: human-readable rendering needs `diag_ctx_add_source` before `lex_into`; already satisfied at both wired call sites.
- **Stale compile cache**: use `VOW_CACHE_DIR=$(mktemp -d)` when validating codegen after the rebuild (known issue).
- **Concurrent-gate flakes**: lone `CompileFailed/LinkFailed` during concurrent bootstrap is contention (known); re-run.
- **Pre-existing failures** (`u64_marker_propagation`, `contracts_tmp_cleanup`, `concrete-block-region-parity`, sandbox e2e SKIP-panics) reproduce on clean main; don't chase.
- **Parse→print→parse idempotency**: unaffected (valid-token lexing unchanged; only previously-silently-skipped input now errors).
- No `vow-clif-shim`, stack-slot, codegen-ordering or C-emitter impact (lexer only); no C-parity risk.
- Bytes the Rust lexer accepts but the self-hosted one lacks would become new hard errors: diffed the Rust `next_token` byte arms
  against lexer.vow's chain (all single-byte tokens present; `is_whitespace` includes 13 so CRLF is fine; ident start/cont match).
  Add a CRLF + all-operator unit test in slice 4 as a guard.
- Commit/PR title must be lower-case conventional commits, e.g. `fix(lexer): report unterminated strings and unknown characters in self-hosted lexer`.

## Out of scope
- Known divergence kept: stopping at the first lex error means an earlier in-band `5usize`/out-of-range literal is not reported
  if a later unknown character exists (Rust would report the earlier one first).
- Unifying `tok_invalid_int`/`tok_invalid_float` with the new `DiagCtx` path; multi-error recovery (continuing after a lex error).
- Invalid-UTF-8 detection, new lexer features, the `ec_name`/diag refactors, other audit findings.
- Making `decl_entry_module_name` diagnostics-aware; Rust `tokenize()` API changes beyond the two error codes.
