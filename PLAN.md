# Plan: native verifier walking skeleton, `vowc verify --backend native` (#1408)

## Goal
Add an opt-in `--backend native` to the self-hosted `vowc verify` that symbolically executes a **single-block, i64/bool, pure** function from the SSA IR, builds an SMT command list, renders one self-contained `.smt2` per claim, runs Bitwuzla as a child process, and reports `Verified` / `VerifyFailed` (counterexample in today's JSON, with span, blame, `vow_id`) / `Skipped` / `tool_not_found`. Everything outside the subset is `Skipped`, never `proven`. Verifier-only work (epic #1398, ADR-1421 scoped exception): **no Rust twin, no C-emitter change**. No syntax/type/builtin change, so `parse → print → parse` idempotency is unaffected, and no `tests/run/` or `examples/` growth is needed.

## Assumptions (decisions made without an operator; post as one `gh issue comment 1408` at the start of implementation)
- **Subset = one basic block ending in `Return`.** `if`, `&&`, `||` (lowered to Branch/Upsilon/Phi, even inside contract clauses), loops and calls are multi-block or calls ⇒ Skipped. Branches/merges are P2.
- **Supported ops**, all at type `i64`/`Bool` only: `GetArg` (i64 params only; a Bool param needs a value format nothing pins), `ConstI64`, `ConstBool`, `WrappingAdd/Sub/Mul/Div/Rem`, `Eq/Ne/Lt/Le/Gt/Ge` on i64 (and `Eq/Ne` on Bool), `BitAnd/BitOr/BitXor`, `Not`, `And`, `Or`, `VowRequires`, `VowEnsures`, `Return`. Everything else (checked `C*` ops, shifts, `IntCast`, other widths, u64, floats, calls, `VowInvariant`, `DebugCall`, `ComplexityDescriptor`, region/linear ops, Phi/Upsilon/Branch) is `Skipped`. Checked ops need the assert+assume pair of `docs/verifier-discipline.md` ("Modelling an abort is not pruning"); half-modelling them is unsound.
- **Skipped reasons use ADR-1430's closed codes**: `function-has-effects`, `ir-non-dominating-read`, `unsupported-opcode` with detail `OpName[ty]` (e.g. `CheckedAdd[i64]`, `WrappingAdd[u64]`, `Call`). Type-qualified detail fits the existing row; no new code. The JSON `reason_code` field is **not emitted in this PR** (my deferral, not an ADR assignment): it forces edits to `diagnostic.schema.json`/`contracts-result.schema.json` + `skills/vow/schemas/` copies (`additionalProperties:false`) and ADR-1430 rejects a message-prefix carrier, so the human message stays plain text (`skipped verification of \`f\`: unsupported-opcode: CheckedAdd[i64]`) and a follow-up (the #1409 op-model-table child) adds the field.
- **Division/remainder follow the spec, not the C model** (`grammar.md:325-328`: zero divisor aborts for `/` and `%`; signed `MIN / -1` aborts for `/`; `MIN % -1 == 0`). SMT `bvsdiv`/`bvudiv` are total (probed: `bvsdiv(5,0)=-1`, `bvsdiv(MIN,-1)=MIN`), so each `WrappingDiv/Rem` site gets its own **abort claims**, **split per condition**: claim A `divisor != 0` (label `division by zero`, text "division or remainder by zero"), and for signed `/` claim B `!(dividend == MIN && divisor == -1)` (label `division overflow`, text "signed division overflow (MIN / -1)"; new `describe_assert_label` entry). Both reported with the unattributed sentinel `vow_id` 4294967293, blame `none`. The claim that failed determines the text — no guessing from the model. Later claims **assume** the earlier abort guards (an aborting run never reaches them): the assert and the assume always come as a pair.
- **ESBMC verdict divergence is expected and spec-justified**: native is stricter on `MIN / -1` for plain `/` (the C model has no such check), so `examples/divide.vow` (`requires y != 0; x / y`) is `VerifyFailed` under native (counterexample `x = MIN, y = -1`) while ESBMC proves it. Record in the PR body and in `docs/spec/cli.md`; the differential-harness child lists it.
- **Claim set**: one claim per `VowEnsures` and per div/rem condition, in IR order; `VowRequires` are assumptions (target function; blame Caller; never claims). **Assumptions are positional**: a `requires` is assumed only for claims after it (a division inside a `requires` clause is itself a claim that must not assume that `requires`). First failing claim in IR order is reported. A function with zero claims is `proven` without a solver call.
- **Query shape**: `QF_BV`, `(set-option :produce-models true)` (mandatory: `get-value` without it makes Bitwuzla exit 1 with `[error] … model generation is not enabled`, probed), params as `declare-const` named by **internal names only** (`p<k>`, `v<id>` — never source names, so no collision/injection and no reserved-symbol path), each IR value as `define-fun v<id>`, assumptions asserted, `(assert (not <claim>))`, `(check-sat)`, `(get-value (p0 … pk))`. `sat` ⇒ failed with model, `unsat` ⇒ claim proven, anything else ⇒ `unknown`/`timeout`/`error`, never proven. Counterexample `var_names` map back to source names from `f.param_names`.
- **Driver is in-process and sequential.** `vowc verify-worker`, memory cap, process-group kill and `--verify-jobs` concurrency are separate P1 children (D11).
- **Solver discovery**: `path_lookup("bitwuzla")`, resolved lazily on the first function that needs a solver (all-Skipped modules do not need it). Not found ⇒ `record_soft_fail(soft_meta, "tool_not_found", …)` so JSON carries `verify_status:"tool_not_found"` (the ESBMC path emits a bare `VerifyFailed` from its pre-flight guard; native intentionally uses the status — "existing tool-not-found status" — pinned by a test). Pin/SHA-256 check of the binary is not done (no hashing builtin; follow-up, documented).
- **Solver invocation**: `bitwuzla --bv-output-format 10 -t <ms> <file.smt2>` via `process_start` + `process_wait_timeout` (runtime SIGKILLs the child itself on timeout and returns -2; no process groups exist and a single bitwuzla has no children). `--timeout` is **per function**: each claim gets the remaining budget. `--timeout 0` never reaches Bitwuzla (`-t 0` is not "expire now": probed to still solve) — it short-circuits to `timeout` without spawning. Probed on local 0.9.0: `sat`/`unsat` exit 0, `unknown` (timeout) exit 0, errors print `[error] …` on stderr with exit 1; after `unsat`/`unknown` `get-value` prints nothing; models print `sat\n(\n  (p0 (_ bv1 64))\n  (p1 …)\n)` (single var on one line; `#b…` without `--bv-output-format 10`). Classify by the **first stdout line**; non-zero exit, stderr `[error]`, unrecognised first line, or `sat` with an unparsable/incomplete model ⇒ `error`.
- **CLI scope**: `--backend <esbmc|native>` accepted on `verify`. `build`, `contracts`, `test` and the legacy `vowc f.vow --verify` path reject `--backend native` with a usage error (exit 1) rather than silently running ESBMC; unknown values rejected everywhere. Under native, `--max-k-step`, `--solver`, `--encoding` are rejected (ADR-1430 interim rule). `--no-cache` accepted (no-op); `--timeout` honoured (seconds, default 300); `--verify-jobs` accepted, ignored; `--replay-cex` and `--perfetto` flow through the existing tail.
- **Verify targets unchanged** (`is_verify_target`, verifier.vow:1225): functions with a `vow` block plus pure *modelable* uncontracted callers of contracted functions. Under native such a pure caller contains a `Call` ⇒ `Skipped` (fail-closed). Effectful callers (`main` with `print_i64`) stay role 2 ⇒ existing `VerificationSkipped` Note only, so fixtures keep their `main`.
- Rust stage-0 `vow` does not implement `--backend`; `cli.md`/help say "self-hosted `vowc` only" until seed delegation (P6). Before editing `cli.md`, `grep -rn "cli.md" vow/ scripts/` for a Rust test syncing the doc with clap; if found, add a marker or parse the flag in Rust (decision recorded in the PR).
- This sandbox has no `bitwuzla` on PATH but a 0.9.0 build at `/home/pmatos/.local/bitwuzla/bin/bitwuzla` (pin is 0.9.1). Local real-solver runs use `PATH=/home/pmatos/.local/bitwuzla/bin:$PATH`; wiring is also tested against a fake `bitwuzla` (idiom of `scripts/parity_c.py`'s fake `esbmc`). Note the version skew in the PR.

## Module design (narrow interfaces; later P1 children deepen these without renaming)
- `vc_term`: term arena in parallel `Vec<i64>`s (op, a, b, aux) + `Vec<String>`; `tm_var`, `tm_bv_const(width, value)`, `tm_bool_const`, `tm_app1/2`; sorts Bool/BV64. No hash-consing/simplifier (separate children replace this seam).
- `vc_smt`: **command list** (`SmtScript`: `SetLogic`, `SetOption`, `DeclareConst`, `DefineFun`, `Assert`, `CheckSat`, `GetValue`) + `smt_render(arena, script) -> String`. The only place that prints SMT text; no other `vc_*` file contains `"(assert"`/`"(declare"` literals (acceptance: query text from a command list). Constants render `(_ bv<uint_to_string(v as u64)> 64)` (negative i64 = two's complement).
- `vc_gate`: `vc_skip_reason(f, m) -> String` (`""` or `"<code>: <detail>"`); order: effects → `ir_non_dominating_read` → single-block/terminator → per-inst (op, type) table. Unknown opcode ⇒ Skipped, never accepted.
- `vc_exec`: `vc_claims(f) -> ClaimSet`: one pass over the block folding instructions into arena terms, `define-fun` per value, positional assumptions, ordered claims `{kind, vow_id, label, script}`. `result` is just the SSA id given to `Return`/the ensures predicate.
- `vc_solver`: `vc_solver_locate()`, `vc_solver_check(script_text, names, budget_ms) -> SolverAnswer {verdict, names, values, raw}`; `mktemp_dir("vow-native")` + `<dir>/query.smt2` (own temp pair — `verify_tmp_path` hard-codes `/esbmc.c`), `fs_write`, `process_start`, `process_wait_timeout`, `process_stdout_for/stderr_for`, `process_kill` after every completed wait (evicts `PROCESS_MAP`), then `fs_remove` + `fs_remove_dir` on every path including timeout/spawn failure. Pure `vc_parse_check_sat`, `vc_parse_model` (accepts `#b…`, `#x…`, `(_ bvN w)`; signed reinterpretation) are unit-testable.
- `vc_cex`: claim + `SolverAnswer` → `VerifyResult` (status, `vow_id` or -1 for abort claims, `var_names` from `f.param_names`, `var_values` signed decimal; abort claims set `raw_output` = `"Violated property:\n  division by zero\n"` / `"…\n  division overflow\n"` so `parse_assert_label` supplies the text via the existing `build_ce_from_result`).
- `vc_native`: `vc_verify_function(f, m, budget_ms) -> VerifyResult`: claims in order → `vc_solver_check` → stop at first non-`unsat`.
- `main.vow` `run_verify_native`: gate ⇒ `VerificationSkipped` Warning (same shape as `skip_if_non_modelable`, native reason) ⇒ `vc_verify_function` ⇒ PROVEN prints `PROVEN`; FAILED ⇒ `build_ce_from_result`; TIMEOUT/UNKNOWN/NOT_FOUND/ERROR ⇒ `record_soft_fail`.

## Verification surface
- No ESBMC property changes, no C-emitter edit ⇒ verifier C parity (`parity.py c`, Section 2c) untouched; `tests/verify-native/` is outside its explicit globs (`full_test.sh:873`).
- **Properties Bitwuzla must decide**: `div_positive` — claim A `y != 0` unsat under `y > 0`, claim B (signed) unsat under `y > 0`, ensures unsat; `overflow_ensures` — `x>0 ⊢ x+x > x` sat for x ≥ 2^62 (vow 1, callee); `rem_unguarded` — `b != 0` sat at b = 0 (4294967293); `signed_div_min` — B sat at `x=MIN, y=-1`; `add_exact` — `x+1 == x+1` unsat.
- **Bootstrap verifies the new modules.** `vc_*.vow` carries no `vow` blocks and pure helpers do not call contracted functions (e.g. `iop_is_terminal` has `requires`; such helpers would become role-1 verify targets). `bootstrap.sh:84-90` fails on any `Skipped`. Check with `build/vowc verify compiler/vc_*.vow` before the bootstrap run. Extern/process users are non-modelable ⇒ role 2 ⇒ Note only.
- Contract authoring: no fixture bounds values to suit the solver; `add_exact`'s guard is a genuine overflow guard.

## Risk areas
- **Soundness (blocker class)**: total SMT division ⇒ per-condition abort claims with assert/assume pairing; fail-closed gate; unparsable/incomplete solver output ⇒ `error`; `sat` trusted only with a fully parsed model; timeout/`unknown` never proven; `get-value` requires `produce-models`. Reviewers grep that `vc_exec`/`vc_solver` contain no SMT text literals.
- **IR traps**: `result` is the SSA id passed to `Return`; ensures is duplicated per return site (n/a for one block); Upsilons may follow terminators (gate rejects Phi/Upsilon rather than ignoring them); dead constants like `ConstI64[MAX]` are not errors; comparison result `ty` is Bool while operand type is in `dv` (`IDATA_INTEGER`); `&&`/`||` never lower to `And`/`Or` (they become branches).
- **Binary fixed point**: new modules change the binary; deterministic iteration (no `HashMap`), claim/param order fixed; structs hold only `Vec`/`String`/ints; annotated `let` for chained field access (CLAUDE.md Gotchas); `Vec`s alias across by-value copies.
- **`concat_vow.sh` and name uniqueness**: the concatenation strips `module`/`use` and flattens, so every fn/struct/const in `vc_*` must be globally unique across `compiler/*.vow` (prefix `vc_`/`VC_`, grep before adding); a missing/mis-ordered entry breaks PR CI (`ci.yml:123,181`) and the bootstrap triple test — likeliest failure.
- **Rust parity of tests**: `vow test compiler/` runs new `test_vc_*.vow` under stage 0 and diffs via `parity.py test`; Section 10b asserts `--filter arith` matches exactly one test (no `arith` in stems); solver-spawning tests stay in the shell tier, unit tests are pure. ADR-1421's requested exemption mechanism doesn't exist; pure tests pass on both compilers so none is built.
- **Process hygiene**: every started handle reaches `process_wait_timeout`/`process_kill`; temp dir removed on every path; `mktemp_dir` honours `TMPDIR`; exit code -1 is ambiguous (signal vs spawn failure) ⇒ both are `error`.
- **Version skew**: local Bitwuzla 0.9.0 vs pin 0.9.1; CI is authoritative; fixtures skip when `path_lookup("bitwuzla")` is empty locally.
- **Equivalence sweep**: nightly `scripts/equivalence.py` rglobs `tests/`, so `tests/verify-native/` also runs through both compilers' ESBMC path; consistent, harmless.
- **Verdict divergence vs ESBMC** (`MIN / -1`) is intentional; the P5 parity gate needs a per-fixture explanation (recorded in `cli.md`/PR).
- **clippy gate** touched only by regenerated `vow/src/skill.rs`. Compile cache: validate codegen with `VOW_CACHE_DIR=$(mktemp -d)`. Memory: no concurrent heavy builds (`-j2`).
