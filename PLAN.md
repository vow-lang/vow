# Plan: f32/f64 IEEE-754 in the native verifier (#1415, part of #1398)

## Goal
`vowc verify --backend native` proves/refutes contracts over `f32`/`f64` using SMT-LIB `FloatingPoint` (RNE, IEEE comparisons, one canonical NaN), models the `u64` side of `parse_f64_bits`/`format_f64_bits`, keeps float `%` `Skipped` (`float-rem-unsupported`), documents the limits, and lands float fixtures that the perf corpus (`scripts/verify_perf.py`) picks up by directory. Native verifier only: `compiler/vc_*.vow`, no Rust twin (CLAUDE.md scoped exception, ADR-2026-10-08-1421). `c_emitter.{rs,vow}` are untouched, so the C-parity rule is not engaged.

## Assumptions (no operator available; override in review)
- **FP term representation**: new `VC_OP_FP_*` op codes (35+) whose printed symbol embeds the rounding mode (`fp.add RNE`), plus a unary `to_fp` op over a BV literal for constants. No new term kind, so `vc_slice` (walks only APP/EXT) and `vc_term_text` need no structural change. A bare `RNE` leaf would be treated by the slicer as an undeclared symbol.
- **FP sort codes** `VC_SORT_F32 = 2032`, `VC_SORT_F64 = 2064` (= 2000 + raw bit width). Fit next to `0` (Bool) and `1000` (array); the same code travels in `model_widths` to the model parser so it knows the field is FP and how many bits.
- **Logic**: stay `QF_BV`/`QF_ABV` for programs with no FP (existing goldens, cache keys, `test_vc_*` pins unchanged). Switch to `QF_BVFP`/`QF_ABVFP` when any id of the function's type table (`vc_ty_table`, after inlining/unrolling) is F32/F64 - not merely when a float *parameter* is declared (literal-only float code like `0.1 + 0.2` has no float params). Verified empirically with local Bitwuzla 0.9.1: `QF_BV`/`QF_ABV` reject `Float32` (`invalid sort`); `QF_BVFP`/`QF_ABVFP` accept BV+FP, push/pop, define-fun with FP `ite`.
- **IEEE compare mapping**: `EQ_F → fp.eq`, `NE_F → (not (fp.eq a b))`, `LT/LE/GT/GE_F → fp.lt/fp.leq/fp.gt/fp.geq`. Never `=`/`distinct`: SMT `=` is structural (single NaN ⇒ `NaN = NaN` is true; confirmed empirically) and `vc_simp_eq` folds `x = x` to true. This matches codegen: Cranelift `fcmp` ordered except `NotEqual` (unordered-or-ne) (`vow-codegen/src/cranelift_backend.rs:1146-1178`).
- **No float casts exist** (the checker rejects every `as` with a float side; `vow-types/src/check.rs:822-837`, `compiler/checker.vow:4110-4161`) and **float negation lowers to ill-typed integer `WSUB[i64]`** (`compiler/lower.vow:3275-3288`). Neither is modelled; negation stays `Skipped: unsupported-opcode` via the gate's strict operand-type checks. ADR Rule 5's "casts follow the runtime" sentence is vacuous and gets an addendum. Fixing the lowerer is out of scope; file a follow-up issue (`fix(lower): float unary minus lowers to integer WSUB`).
- **f32 literals**: the self-hosted lowerer only ever emits `CONST_F64` (literals are always f64). `CONST_F32` (`dv` = raw f32 bits, `module_io.vow:752-754`) is modelled anyway via `((_ to_fp 8 24) #x........)` and covered by hand-built-IR unit tests only.
- **Hooks (`u64` side exact)**: no language construct converts `u64` bits to `f64`, so "exact" means: `format_f64_bits(bits)` consumes its `u64` argument exactly (no information dropped) and returns an opaque String object; `parse_f64_bits(s)` returns a `u64` that is a fresh **unconstrained** BV64, deterministic per String object (memoised on the argument's object id). No NaN-payload constraint: that would model string-side parser semantics (issue keeps the string side opaque), enlarge the trusted base and depend on Rust parse behaviour; over-approximation keeps proofs sound. The String side is opaque (no length/content model). `parse_f64_bits("literal")` stays `Skipped` (`CONST_STR`/`__vow_string_literal` unmodelled) - documented limit.
- **Counterexample float rendering**: shortest round-trip decimal via `format_f64_bits` (already used by `ir_printer.vow:192`), NaN/`inf`/`-inf` as Rust Display prints them; an f32 value is widened exactly to f64 first and printed as that f64. Float counterexamples are never replayed (`replay_one_ce` skips non-i64/u64/bool, `compiler/main.vow:840-843`), so those fixtures carry `replay-skipped` with the harness's exact reason text (pattern: `fail/u8_wrap_post.vow`).
- **Perf**: FP bit-blasting (`fp.div`/`fp.mul` on f64 especially) may be slow. Fixtures must keep honest contracts; if a heavy op is too slow within the default timeout, use f32 / fewer heavy ops in the fixture (never weaken a contract) and record the limit. Measure with real Bitwuzla 0.9.1 (present at `~/.local/bin/bitwuzla`).

## Risks
- **Simplifier soundness (trusted base)**: any rule firing on FP terms is a silent false-`proven`. Mitigation: FP ops are fresh op codes outside every fold/identity/reflexive list; comparisons never use `VC_OP_EQ`/`DISTINCT`; Slice 1 tests pin this; `test_vc_term` random-DAG evaluator is not extended to FP (no independent FP evaluator) - state as a limit.
- **Logic string drift**: switching logic only when FP is present keeps all non-float goldens/cache keys stable; a float query under `QF_BV` would be a solver `[error]` → `VC_ANS_ERROR` (fail closed, never `proven`).
- **`vc_format_int` silently prints `0` for floats** and **`vc_model_symbol_name` prints the raw sort code**: both fixed in Slice 4 before any float counterexample can surface; Slices 3 and 4 must land in the same PR (no intermediate float-failing build on `main`).
- **Perf gate** (epic acceptance 3: geomean ≤ ESBMC, no fixture >1.25×): FP bit-blast cost; fixtures are only added where Bitwuzla finishes; model cost is documented not hidden.
- **Spurious counterexamples** from over-approximations (canonical NaN, opaque String, unconstrained slot reads): these cannot be replayed; always `replay-skipped`; proofs stay sound (over-approximation), refutations involving NaN payload/sign or String content are documented unreliable.
- **Fixed point / bootstrap**: no lowerer/codegen change, so the binary fixed point is untouched; new `vc_*` code must itself verify within bounds (epic P5) - keep functions small, avoid chained field access on struct values (annotated `let` bindings, CLAUDE.md gotcha), `BTreeMap`-free.
- **Generated blocks**: `vc_ops.vow` `catalogue_verifier_known` is generated; never hand-edit between `GENERATE:OPERATIONS` markers; run the generator and `--check`.
- **Help/skill embed drift**: spec edits require `generate_help.py` and rebuilds; the Rust crate embeds `skills/` via `vow/src/skill.rs` (the Rust compiler's `cargo test -p vow` may check text) - run `cargo test --all` once for the doc-surface tests.
- **Negation lowering bug** is exposed (not caused) by this issue: documented, fixture-pinned, follow-up filed.
