# Plan: native k-induction cut for a Vec written in a loop (#1645)

## Goal
`vowc verify --backend native` proves a true contract over a `Vec` filled by a loop past the 64-iteration unwind
when the loop carries an inductive invariant (`v.len() == i`), by havocing the loop-written Vec's `(array, length)`
at the loop header of the induction cut, exactly as header Phis are havoced. Fails closed everywhere else.

## Assumptions (decided without the user)
- Native verifier only (`compiler/vc_*.vow`): scoped exception in CLAUDE.md, no Rust twin, no C-emitter change, no `parity.py c` impact. Verify with `build/vowc` only.
- **Scope = `Vec` only.** `String` mutations (`vc_str_kind_mutates`) keep making the function `NA` (ADR-1422 #1657 addendum line ~635); String havoc is a follow-up.
- **Only Vecs defined outside the loop are havoc'd.** A mutated receiver defined inside the loop (a `Vec::new()` in the body) or by a `Phi` stays `NA` (status quo): exit-Phis from `vc_close_values` could carry such an object past the loop and the model has no story for it.
- The issue says "fixtures `tests/verify-native/unknown/vec_loop_*` move to `pass/`". Inspected: none of the three can move. `vec_loop_len_invariant_not_inductive` has invariant `i <= n` (says nothing about the Vec), `vec_loop_symbolic_len` has no invariant, `vec_loop_len_wrong_post` is a false post. They stay (comments corrected). New `pass/` fixtures carry the real invariant. Recorded on the PR.
- `vec_last_element` control (`ensures result[n-1] == 7`) needs a *contents* fact; its generated invariant is length-only, so after the fix it stays `unknown` (honest incompleteness: array is havoc'd). Resolve empirically in slice 5: strengthen the generator's invariant to `i <= n && v.len() == i && (i < n || v[n-1] == 7)` (the `&&` puts the length fact before the guarded `get`) (an invariant is a proof annotation, not the contract, so this does not weaken any `ensures`); if it still does not verify, keep that shape in `KNOWN_DISAGREEMENTS` re-keyed to a new follow-up issue (file with `gh issue create`), not #1645.

## Design
0. **Marker is invisible to the gates (checked).** `vc_gate` (`vc_gate.vow:353`, `vc_vec_shape_detail` `vc_vec.vow:364`) runs on the original function before closing/cutting, never on the cut `g`; the cut's own re-check `vc_unrolled_detail` (`vc_cfg.vow:225`) is CFG-only (terminators, loop shape, Phi head, Upsilon). So the marker follows the existing `__vc_havoc` pattern (extern call recognised by `vc_is_havoc_vec`, not a Vec op kind). The implementer must still assert in slice 2 that the cut of a Vec loop passes `vc_unrolled_detail` and `ir_non_dominating_read` (otherwise `vc_induct.vow:600` silently returns `NA`); if either pass turns out to reject the marker, whitelist `vc_is_havoc_vec` there explicitly.
1. In `vc_induct_cut`, replace `vc_induct_vec_written_in_loop` (bool) with `vc_induct_vec_havocs(f, li, rpo, def_blk) -> VcVecHavocs` returning `ok` plus, per loop `j`, the list of receiver ids to havoc. `ok=false` (=> `NA`) when a mutating instruction is a String op (distinguish with the existing `vc_str_kind_mutates`; `vc_vec_kind_mutates` stays as is because `vc_step_applicable`, `vc_unroll.vow:306`, also uses it and the k-induction step case must keep refusing Vec-written loops), or its receiver (arg 0) is defined by a `Phi`, or defined in a block that is a member of loop `j` (use `vc_def_table` from `vc_loops.vow:256` for def blocks; a parameter/pointer with no def block counts as outside). A receiver mutated in loop `j` is recorded for every loop whose chain (`vc_in_loop(li, b, j)`) contains the mutating block, so outer loops of a nest also havoc it. Dedup per loop; deterministic ordering (ascending instruction order, no `HashMap`) for the binary fixed point.
2. `vc_induct_rebuild_block`: for a loop-header block of the original function (`li.loop_of_header[b] >= 0`), after the leading Phis (now havoc calls) insert, per recorded receiver, a fresh-id instruction `IOP_CALL`/`IDATA_CALL_EXTERN`, `ds = VC_INTERNAL_HAVOC_VEC()`, `ty = ITY_UNIT()`, `args=[receiver]`, ids from `st.next_inst` (the same counter `vc_induct_copy_end` uses; clones use ids >= `n_ids`, keep the counter shared and bump it). Copies (entry/back) are untouched: the entry copy claims the invariant on the entry state, the back copy claims it on the state the body produced. Phis must stay first (`vc_phi_head_detail`).
3. Executor: in `vc_walk_inst` add `else if vc_is_havoc_vec(inst)` that calls `vc_vec_havoc`. It does `s = vc_vec_slot(...)` (creates the slot, adds the `len < 2^63-1` representation fact to `assumed`, which holds on every path), declares fresh `vh<N>_varr` (array sort) and `vh<N>_vlen` (64) via `vc_agg_declare`, adds `vc_tm_app2(ar, VC_OP_BVULT(), len, vc_vec_len_mask(ar))` to `assumed`, and `vc_vec_write(vv, ar, hdr, s, bi, arr, len)`. Define no value (Unit). Fresh names come from `vc_vec_fresh_name` so they are unique per function and stable across rounds.
4. Soundness argument (put in the ADR): header-proper state = (arbitrary array, arbitrary length < mask) ∧ invariant assumed; claims: invariant on entry copy (base), invariant on back copy (step), loop-exit/ensures claims on the exit side of the header. Reads of other Vecs flow unchanged. Induction only ever *proves* (`VcInduction.proves`, vc_native.vow:356-383); a sat answer is discarded and the bounded verdict stands, so a false contract can never become `Verified`.
5. Unchanged: `vc_step_applicable` (`vc_unroll.vow:287-`) keeps refusing Vec-written loops (k-induction step case would need the same havoc; follow-up). `vc_induct_agg_written_in_loop` stays.

## Verification surface
- No contract, codegen, C-model change; ESBMC path untouched. New SMT shape: Vec havoc adds two fresh declared constants (array + 64-bit) and one `bvult` fact per havoc'd Vec per loop header. Properties proven natively: invariant base/step, `ensures` on the exit side, plus existing push/get bounds claims (a `get` in the loop body now reads the havoc'd length, so index claims need the invariant to bound it — expected).
- Check `vc_slice.vow` (query slicing/per-clause verdicts) handles the new declared constants: run `build/vowc test compiler/ --filter test_vc_slice` and a fixture with `VOW_VERIFY_NO_SLICE`-style toggle if present (`vc_slicing_enabled`).
- Cache: native `unsat` cache (`vc_cache.vow`) keys on query text; always use `--no-cache` for "green" claims (CLAUDE.md).

## Risks
- **Soundness (highest):** leaking the entry state into the havoc'd header (what the old gate prevented). Guard: marker must be in the header proper only; fixture 4 (`contents_not_in_invariant`) and the corpus bug-class controls must stay non-`Verified`. An unmodelled mutation path (receiver via `Phi`, in-loop allocation, String) must stay `NA`.
- Nested loops: the inner loop's header proper havoc sits inside the outer body; confirm entry-copy/back-copy block merges via `vc_vec_enter` give the inner header the outer's havoc'd state, not a stale one (slice 2 nested test + fixture 3).
- Binary fixed point: new instruction ids come from `st.next_inst`; iteration order must be index-based (no map iteration). Run `scripts/bootstrap.sh --skip-cargo --no-cache` on the final SHA, record head SHA and `scripts/seed.toml` pin in the PR checklist (CLAUDE.md rule).
- Verifier performance: arrays in the query leave pure bit-vector logic only when a Vec exists (already the case for Vec functions); no new quantifiers.
- Slow gates: bootstrap ~5 min, `full_test.sh` ~40 min, `build/vowc test` ~3 min/file; run foreground with explicit timeouts. Known unrelated pre-existing failures (see memory) — compare with clean `origin/main`.
- Not applicable (no change): `parse -> print -> parse` idempotency (no parser/printer change); verifier C parity / `scripts/parity.py c` (no `c_emitter.*` or lowering change); `cargo clippy` (no Rust change); `tests/run/` and `examples/` need no growth.
- Commit/PR title must be lower-case conventional: e.g. `feat(verify): cut a loop-written Vec for induction in the native verifier`.

## Out of scope
- String havoc in the cut; Vecs allocated inside the loop; `Phi`-merged Vec receivers.
- Extending `vc_step_applicable` (k-induction step case, #1425) to Vec-written loops.
- Automatic invariant/contents synthesis; quantified contents invariants.
- Any Rust compiler, `c_emitter.*`, spec (`docs/spec/*`) or ESBMC-path change; formatting/refactors of `vc_induct.vow` beyond the replaced predicate.
