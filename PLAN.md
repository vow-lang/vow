# Plan: add centralised "Do nots" section to the Vow skill entrypoint (#459)

## Goal
Add a short, imperative `## Do nots` section near the top of the generated `skills/vow/SKILL.md`
entrypoint, so the agent-bug classes that `contracts.md` and `CLAUDE.md` scatter are read first.
Size: **Small** — one generator edit plus its checked-in generated outputs; no language, CLI, IR,
codegen or verifier change.

## Assumptions
- Single source = the generator. `SKILL.md` is generated by `scripts/generate_help.py::build_skill_entrypoint`
  (`scripts/generate_help.py:988`), mirrored into `skills/vow/SKILL.md`, `vow/src/skill.rs`
  (`GENERATE:SKILL_FULL`) and `compiler/main.vow` (`GENERATE:SKILL_FULL`). Editing the generator once and
  regenerating satisfies the dual-compiler rule; hand-editing any of the three outputs is wrong. (best guess)
- Entrypoint only. The `vowc skill print` bundle (`build_skill_bundle`, built from `docs/spec/index.md`) is
  not touched; the issue names "the entrypoint `SKILL.md`". Do-nots in the bundle is a follow-up. (best guess)
- The issue's "Don't scrape terminal prose when `--json` is available" cannot be written literally: there
  is **no `--json` flag** (`grep -- --json docs/spec/cli.md` is empty). `vow build`/`vow verify` emit one
  JSON object to stdout by default (`docs/spec/cli.md:319-321`); `--help --human` is the prose form
  (`docs/spec/cli.md:278-285`). The rule is therefore "parse the stdout JSON; do not scrape stderr or
  `--human` text". Writing `--json` would violate the skill's own "don't invent CLI fields" rule. (best guess)
- No new spec text: nothing in syntax/semantics/CLI changes, so `docs/spec/*.md` is untouched; every
  rule restates an existing spec rule (`contracts.md:408-436`, `cli.md:305,330`). (best guess)

## Content of the section (final wording is the implementer's; rules and sources are fixed)
Heading `## Do nots`, placed before `## Installed toolchain (live)` so it is not pushed below the
~200-line `--help` dump the live probe injects. Six one-line bullets, ASCII only, each starting `Do not`:

1. Do not weaken, cap or distort a contract to make verification pass; fix the code or report that the proof is out of reach. (`contracts.md:412,436`; CLAUDE.md "Contract Authoring")
2. Do not add verifier-motivated bounds (`n <= 10`, length/capacity caps, overflow-guard bounds) to `requires`; keep only real domain constraints and use `+!`-style checked operators for overflow. (`contracts.md:408,414-434,438`)
3. Do not use `--no-verify` to get past a real verification failure; it only skips the proof (status `Unverified`). (`cli.md:305,330`)
4. Do not report a program as verified unless `status` is `Verified`; `Unverified` and `Skipped` are not success. (`cli.md:328-332`)
5. Do not invent CLI flags, JSON fields, syntax or builtins; check `build/vowc --help` and the reference files first.
6. Do not scrape terminal prose; parse the JSON object on stdout (`status`, `diagnostics`, `counterexamples`) and use `--human` only for people.

Constraints on the text (they protect the generated payloads): no `"` or `\` characters (they are
escaped into Vow string literals by `_vow_escape`), no `"##` sequence (Rust raw-string delimiter,
`_rust_raw_string`), every line short (Vow payload chunking, `VOW_LITERAL_CHUNK_BYTES`).

## Risks
- **Generated-file drift**: forgetting to regenerate, or hand-editing a mirror, fails `help/skills-dir-drift`
  and the Rust drift test. Mitigation: Step 2 + `--check`; implementer must not edit the three outputs.
- **Stale regeneration noise**: if the generator run touches more than the five expected files, the
  checkout is behind main; do not commit extras (surgical-changes rule).
- **Non-ASCII**: the Rust and checked-in SKILL.md would keep a non-ASCII char (e.g. an em-dash), but
  the self-hosted bundle payload in `compiler/main.vow` shows spec dashes transliterated (`--`), so a
  non-ASCII bullet could make `vowc skill install` differ from the Rust install. The section must be
  ASCII-only (slice 4 asserts it); also use `--` or `;`, never an em-dash, in bullets.
- **Literal escaping**: quotes/backslashes in bullets get escaped into Vow literals and Rust raw strings;
  slice 4 plus ASCII-only wording prevents a broken `main.vow` payload. A broken payload would only show
  up at self-hosted compile time, so run the Python tests before regenerating.
- **Bootstrap fixed point**: `compiler/main.vow` grows by one string payload; deterministic, so the
  binary fixed point is unaffected (no codegen ordering, `BTreeMap`/`HashMap`, or stack-slot change).
- **`parse -> print -> parse` idempotency / clippy**: untouched (no Rust logic added; the optional test
  assertion is test-only and is covered by `cargo clippy --all --all-targets -- -D warnings`).
- **Wording divergence from the issue**: rule 6 deliberately replaces the non-existent `--json` flag
  (see Assumptions); noted in the PR body so a reviewer can override.
- **codecov/patch**: the change is Python + generated text; test-only Rust lines in `skill.rs` are
  executed by `cargo test`, so no uncovered new Rust lines.
