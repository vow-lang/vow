# Plan: split `fs_remove_dir` (rmdir) from new `fs_remove_dir_all` (recursive) — issue #476

## Goal
Make `fs_remove_dir` fail-closed on non-empty directories (`std::fs::remove_dir`, POSIX `rmdir`) and add `fs_remove_dir_all` (`std::fs::remove_dir_all`) as the explicit recursive builtin (issue resolution option 1). Land in both compilers + runtime + spec/help in one PR; every in-repo caller is re-audited so no behaviour silently changes.

## Assumptions
- Option 1 (rename + split) chosen over docs-only: the footgun is removed, not documented. Best guess, per issue text.
- `fs_remove_dir` keeps its name but changes semantics (recursive -> non-recursive). Breaking for external callers that relied on recursion; no deprecation shim (a second recursive alias would keep the footgun). Called out in the PR body. In-repo callers are migrated explicitly (table below).
- Same signature/effects for both: `fn(path: String) -> i64 [io]`, 0 ok / -1 failure, same null/invalid-UTF-8 behaviour as today.
- `verifier.vow::cleanup_verify_tmp_path` uses `fs_remove_dir_all` (preserves today's behaviour: removes the mktemp dir even if ESBMC left sibling files). Issue notes recursion is fine there.
- `mutants_main.vow` lock dir is created by `fs_mkdir` and never populated -> `fs_remove_dir` (rmdir) is correct and fail-closed.
- No ADR needed (no architecture decision; semantic fix of a builtin). No new C-model/verifier impact (builtins are `[io]`, not modelled).

## Risks
- **Bootstrap ordering**: `compiler/verifier.vow` will call `fs_remove_dir_all`, which an old `build/vowc` cannot type-check. Stage 0 (Rust, rebuilt first) must know the builtin; run `cargo build --release -p vow` then `scripts/bootstrap.sh --skip-cargo`. No `scripts/seed.toml` exists yet, so no seed pin to record. Stale compile cache: use `VOW_CACHE_DIR=$(mktemp -d)` (runtime semantics changed under the same source rev).
- **Silent semantic change of `fs_remove_dir`**: any caller missed by the audit now fails (returns -1, mostly ignored) and leaks a dir. Mitigated by the full grep above (all `.vow`, `.rs`, `.py`, docs); implementer must re-grep `fs_remove_dir\b` at the end.
- **Hand vs generated edits**: the `one_param_returns_i64` lists are hand-maintained; forgetting them yields an undeclared-extern failure at codegen/link time, not at type check. The step-1 fixture catches it.
- **Binary fixed point**: adding one `env_define_fn` and match arms is deterministic; no map-type or ordering changes. Run the bootstrap triple.
- **Memory bound**: bench program must keep its RSS; only the call target changes.
- **Rust clippy `--all-targets`**: new runtime tests must be warning-free.
